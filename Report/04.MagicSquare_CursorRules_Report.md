## 0. Executive Summary

본 문서는 MagicSquare_XX 저장소에서 Cursor Agent가 **항상 따라야 하는 규칙(프로젝트 룰)** 을 표준화하기 위해 작성되었다. 규칙은 다음 두 형태로 관리한다.

- **핵심 규칙(실제 적용)**: `.cursor/rules/*.mdc` (YAML frontmatter + Markdown 본문)
- **규칙 원본/설계 템플릿(참조)**: `.cursor/magicsquare-rules.yaml` (도메인·아키텍처·TDD·금지사항·구조 요약)

목표는 “코드를 잘 짜는 팁”이 아니라, 문제 정의에서 합의된 1차 범위(**검증/판정 우선**)와 ECB 아키텍처, Dual-Track TDD를 **지속적으로 강제**하여, 대화/코딩 중 의사결정이 흔들리지 않게 하는 것이다.

---

## 1. Rule System 개요

### 1.1 `.cursor/rules/*.mdc` 규칙 파일

각 규칙 파일은 상단 YAML frontmatter로 적용 조건을 가진다.

- `alwaysApply: true`: 모든 작업/대화에 항상 적용
- `globs: **/*.py` + `alwaysApply: false`: 특정 파일 패턴 작업 시에만 적용

### 1.2 이 프로젝트의 룰 분해 원칙

- **한 파일 = 한 주제** (Project / Architecture / TDD / Forbidden / Code Style)
- **항상 적용 vs 파일 범위 적용**을 분리하여 불필요한 간섭을 줄인다.
- 내용은 “요약 + 금지/허용 + 책임 경계” 중심으로 작성한다.

## 3. `.cursor/magicsquare-rules.yaml`과의 관계

`.cursor/magicsquare-rules.yaml`은 본 프로젝트의 규칙을 “한 문서로 묶어” 볼 수 있는 설계 템플릿 역할을 한다. 다만 Cursor의 룰 엔진은 `.mdc` 기반 사용이 일반적이므로, 실제 적용 규칙은 `.cursor/rules/*.mdc`를 기준으로 한다.

권장 운영 방식:

- 변경 제안이 생기면 **먼저** `magicsquare-rules.yaml`에서 규칙 항목을 업데이트(합의 문서)
- 이후, 실제 적용을 위해 해당 주제의 `.mdc` 파일에 반영(실행 규칙)

## 4. 변경/확장 가이드 (Rule Maintenance)

### 4.1 새로운 룰을 추가해야 하는 경우

- 주제가 기존 룰과 독립적일 때: 새 `.mdc` 파일 추가 (예: `magicsquare-logging.mdc`)
- 특정 파일군에만 필요한 규칙일 때: `globs`로 범위를 제한

### 4.2 기존 룰을 수정해야 하는 경우

아래 항목은 “프로젝트 정체성”에 가까워서 변경 시 보고서/테스트와 동시 변경을 요구한다.

- Profile id (`MS4X4_STD_V1`)
- magic constant 34, magic lines 10
- verdict set (`Valid/Invalid/InputError`)
- ECB 의존 방향
- TDD 브랜치 정책 (spec/red/green/refactor)

### 4.3 중복/충돌 방지 원칙

- 같은 금지사항을 여러 파일에 반복하지 않는다.
- 전역 룰은 “핵심만”, 세부 스타일은 `globs` 룰로 제한한다.

## 5. Quick Checklist (작업 시작 전/후)

작업을 시작하기 전:

- Profile이 `MS4X4_STD_V1`인지
- 1차가 검증(판정)인지, 생성/UI가 섞이지 않았는지
- ECB 레이어 경계가 유지되는지
- TDD 단계(spec/red/green/refactor)가 현재 작업과 일치하는지

작업이 끝난 후:

- `InputError`/`Invalid`에서 위반 사유가 비어 있지 않은지(I-7)
- 동일 입력 → 동일 결과(I-5)를 깨지 않았는지
