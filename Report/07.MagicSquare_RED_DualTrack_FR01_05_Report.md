## 0. Executive Summary

본 문서는 **Dual-Track UI + Logic TDD**의 RED 단계에서, 구현·테스트 코드 없이 **Track A(Boundary/UI)** 와 **Track B(Domain/Logic)** 의 실패 테스트 설계표를 고정한다.

핵심 계약:

| 구분 | 내용 |
|------|------|
| **입력** | 4×4 `int[][]`, `0`=빈칸(정확히 2개), 값 `0` 또는 `1~16`, non-zero 중복 금지 |
| **출력** | `int[6]` = `[r1,c1,n1,r2,c2,n2]`, 좌표 **1-index** |
| **마방진 상수** | M = **34** (`MagicConstant` SSOT) |
| **검사 순서** | null → size → empty count → value range → duplicate (short-circuit) |
| **Boundary 실패** | Failure envelope `E001`~`E005` (Python 예외 아님) |
| **격리** | invalid 입력 시 `SolvePartialMagicSquare.execute` **0회** (U-FLOW-02) |
| **Logic** | Domain Mock **금지** |

**테스트 건수:** Track A 13건 + Track B 14건 = **27건** (RED 설계).
