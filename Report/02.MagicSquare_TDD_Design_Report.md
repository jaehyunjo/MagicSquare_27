## 0. Executive Summary

본 문서는 4×4 격자에 대한 **마방진 판정 기준**을 TDD로 구현하기 **전**에 고정하는 산출물이다. 문제 정의(STEP 1~5)에서 확정된 **Invariant I-1 ~ I-8**과 우선순위(`I-4 → I-1~I-3 → I-5, I-7 → I-6 → I-8`)를 **검증 역할**에만 매핑하며, **생성 · 검증 · 표현**은 논리적으로 분리하고 1차는 **검증**만 다룬다.

고정하는 핵심은 다음과 같다. **(1)** 1차 입출력 계약(격자 표현, 허용·거부 입력, 판정 결과 타입). **(2)** 4×4 표준 **마법 선 10개** 목록(I-4). **(3)** 마법 상수 **34**와 I-1~I-3 검증 책임 경계. **(4)** I-7에 따른 `InputError`와 “거의 맞음” 금지. **(5)** Vertical Slice S0~S5와 red/green/refactor 브랜치별 Definition of Done. **(6)** 실행 가능한 테스트 케이스 명세 **18건**(TC-001 ~ TC-018).

`spec` 브랜치에서는 본 문서 승인만이 완료 조건이며, `red`/`green`/`refactor`에서는 각 Slice에 명시된 **실패 테스트 추가 → 최소 통과 → 동작 동일 리팩터**만 수행한다. 성공 기준은 “한 격자를 맞춘다”가 아니라, **동일 기준·동일 입력에 동일 판정(I-5)** 이고, 실패 시 **명시적 사유(I-7)** 가 남는 것이다.

**문제 정의 보고서와의 관계:** [01.MagicSquare_ProblemDefinition_Report.md](01.MagicSquare_ProblemDefinition_Report.md)의 진짜 문제 정의·STEP 분석·I-1~I-8 정의는 **재서술하지 않고 참조**한다. 본 문서는 그 불변량을 **테스트 가능한 계약·시나리오·슬라이스 순서**로 번역한 **TDD 설계층**이다.

- 특정 해를 “예쁘게” 보여 주는 것만을 목적으로 한 UI

### 1.4 README 「아직 정하지 않은 것」— 결정·옵션

#### (1) 1차 범위: 검증만 vs 생성 포함 vs UI

| 구분 | 결정 |
|------|------|
| **권장 결정 (A)** | **1차 = 검증만**. 생성·UI는 2차. |
| **근거** | README 설계 원칙 ① “판정을 생성보다 먼저”; 문제 정의 보고서 STEP 4~5의 역할 분리·TDD 통제 대상이 “올바른 격자 정의”이지 산출물 완성이 아님. I-6·I-8은 선택 불변량으로 2차가 자연스러움. |

#### (2) 마법 선 집합(행·열·대각 외 추가 여부)

| 구분 | 결정 |
|------|------|
| **권장 결정 (A)** | 1차 마법 선 = **행 4 + 열 4 + 주대각 1 + 반대각 1 = 10선**. 꺾인 대각(broken diagonal)·코너 2×2 블록 합 등은 **포함하지 않음**. |
| **근거** | 4×4 짝수 차수에서 널리 쓰는 **표준 마방진 정의**와 README/문제 정의의 “행·열·대각” 서술 일치. I-4(기준 고정)를 최소 집합으로 먼저 동결. |
| **대안 (참고)** | (B) 10선 + 4개 꺾인 대각 → 전통 일부 변형과 맞지만 1차 범위·테스트 수 증가. (C) 설정 가능 선 집합 → I-4는 “실행마다 동일”이지 “사용자가 매번 다르게”가 아님; 2차에 **프로필**로 도입 가능. |

#### (3) 부분 배치(I-8) 1차 포함 여부

| 구분 | 결정 |
|------|------|
| **권장 결정 (A)** | **1차 미포함**. 빈 칸·미채움은 완전 배치 검증 모드에서 **`InputError`** (`INCOMPLETE_GRID`). `Partial` 판정·I-8 규칙은 **2차**. |
| **근거** | 문제 정의의 “완성 시점 모호함”은 I-8로 다루되 우선순위 최하위. 1차는 완전 스냅샷에 집중해 I-1~I-3·I-7 계약을 단순화. |
| **대안** | (B) 1차부터 `Partial` 도입 → 교육·힌트에 유리하나 시나리오·계약이 배로 증가. **1차 권고: (A).** |

#### (4) 언어·런타임

| 구분 | 결정 |
|------|------|
| **권장 (설계 단계)** | 본 문서·테스트 명세는 **언어 중립**(Given/When/Then, row-major 16튜플). |
| **구현** | Decision Log **D-001**에 위임. TDD 슬라이스·TC-ID는 언어와 무관하게 유지. |

## 2. Domain Glossary & Contracts

### 2.1 용어집

| 용어 | 정의 |
|------|------|
| **격자(Grid)** | 4행×4열, 총 16 **셀**을 가진 고정 크기 구조. |
| **셀(Cell)** | `(row, col)` 위치의 하나의 칸; 0-based 또는 1-based는 **표현 어댑터**에서 통일(내부 계약은 0-based 권장). |
| **배치(Placement)** | 16셀 각각에 값이 할당된 **스냅샷**. |
| **완전 배치** | 16칸 모두 값이 있고 `null`/빈 칸이 없는 배치. **1차 검증 입력.** |
| **부분 배치** | 일부 칸만 값이 있거나 빈 칸 표현이 있는 배치. **2차(I-8).** |
| **마법 선(Magic Line)** | 합을 비교하는 셀 인덱스 집합. I-4로 **고정 목록**. |
| **마법 상수(Magic Constant)** | 모든 마법 선이 가져야 하는 공통 합. 4×4·1~16에서는 **34**(I-3). |
| **판정(Verdict)** | 배치에 대한 최종 분류: `Valid`, `Invalid`, `InputError` (1차). |
| **위반(Violation)** | 특정 불변량 실패를 기록한 구조화 항목(코드, 선 ID, 기대·실제 등). |
| **판정 기준(Profile)** | 마법 선 목록 + 숫자 도메인 + 완전/부분 모드. 1차는 **단일 고정 Profile**. |

### 2.2 입력 계약

#### 격자 표현

| 안 | 설명 | 1차 권장 |
|----|------|----------|
| **1안 (권장)** | `4×4` 정수 행렬 또는 **row-major 16튜플** `(v0,…,v15)` — `v_{4r+c}` = 행 `r`, 열 `c` | ✅ |
| **2안** | 좌표+값 목록 `[(r,c,v), …]` 길이 16 | 어댑터로 1안 변환 |
| **3안** | 중첩 없는 flat `length=16` + `rows=4` 메타 | 1안과 동등, 메타 필수 |

#### 허용·거부 (1차 · 완전 배치 모드)

| 입력 조건 | 처리 | 판정 | 대표 사유 코드 |
|-----------|------|------|----------------|
| 행·열이 4×4가 아님 | 거부 | `InputError` | `INPUT_DIMENSION_MISMATCH` |
| 16칸 미만·빈 칸·null | 거부 | `InputError` | `INCOMPLETE_GRID` |
| 비정수·NaN | 거부 | `InputError` | `INPUT_NON_INTEGER` |
| 16칸 모두 정수, 값 일부가 1~16 밖 | 규칙 위반 | `Invalid` | `I1_VALUE_OUT_OF_RANGE` |
| 1~16 각각 정확히 1회 아님(중복·누락) | 규칙 위반 | `Invalid` | `I1_DUPLICATE` / `I1_MISSING` |
| 위 도메인 통과 후 선 합 불일치 | 규칙 위반 | `Invalid` | `I2_LINE_SUM_MISMATCH` |
| I-1~I-2 모두 통과 | 수용 | `Valid` | (위반 목록 빈) |

**정책:** 구조·형식 오류는 `InputError`, **채워진 완전 격자**에서 도메인·합 실패는 `Invalid`. “17이 하나 있지만 나머지 합은 34” 같은 경우 **`Valid` 금지**(I-7).

### 2.3 출력 계약

#### 판정 결과 (1차)

```text
VerdictResult {
  verdict: Valid | Invalid | InputError
  violations: Violation[]   // verdict != Valid 일 때 1개 이상 필수
  magicConstantExpected: 34  // Invalid·Valid 모두에서 기대값 명시 가능(선택 필드)
  profileId: "MS4X4_STD_V1"  // I-4 동일성 식별
}
```

| verdict | 의미 | I-7 |
|---------|------|-----|
| `Valid` | I-1, I-2, I-3, I-4(동일 Profile) 모두 만족 | — |
| `Invalid` | 완전 입력이나 도메인·합 규칙 위반 | “거의 맞음”으로 완화 금지 |
| `InputError` | 격자 구조·타입·완전성 실패 | 조용한 무시·기본 Valid 금지 |

#### 위반 항목 (최소 필드)

```text
Violation {
  code: string           // 예: I2_LINE_SUM_MISMATCH
  invariantId: I-1 | I-2 | …
  lineId?: string        // 예: R2, C0, D_MAIN
  expected?: number
  actual?: number
  detail?: string        // 사람 읽기용; 판정 로직은 code·수치에 의존
}
```

**I-5:** 동일 Profile·동일 완전 배치 → `verdict` 및 `violations` 집합(코드·lineId·expected·actual) **동일**(순서는 정렬 키로 안정화 권장).

**I-7:** `Invalid`/`InputError`인데 위반 목록이 비어 있으면 안 됨. “15/16 선만 맞음”을 `Valid`로 두지 않음.

### 2.4 마법 선 정의 (I-4)

**Profile ID:** `MS4X4_STD_V1`  
**마법 상수:** `M = 34` (I-3: `4×4`, 합 `1+…+16` 의 1/4)

| lineId | 유형 | 셀 (row, col) 0-based |
|--------|------|------------------------|
| `R0`~`R3` | 행 | 행 `r`의 `(r,0)~(r,3)` |
| `C0`~`C3` | 열 | 열 `c`의 `(0,c)~(3,c)` |
| `D_MAIN` | 주대각 | `(0,0),(1,1),(2,2),(3,3)` |
| `D_ANTI` | 반대각 | `(0,3),(1,2),(2,1),(3,0)` |

**선언:** 모든 판정은 위 **10선**에 대해서만 합을 계산한다. 판정 호출 간 선 목록·`M`·Profile ID는 **변경되지 않는다**(I-4). 추가 선 검사는 **다른 Profile**로 취급하며 1차 범위 밖이다.

## 3. Invariant → Verification Map

| Invariant | 검증 책임(역할 수준) | 1차 테스트 | 실패 시 관측 가능한 신호 |
|-----------|----------------------|-------------|---------------------------|
| **I-1** | 숫자 집합 규칙 — 1~16 각 정확히 1회 | Y | `Invalid`, `I1_DUPLICATE` / `I1_MISSING` / `I1_VALUE_OUT_OF_RANGE` |
| **I-2** | 마법 선 합 동일성 — 10선 각각 `M` | Y | `Invalid`, `I2_LINE_SUM_MISMATCH` + `lineId`, `actual≠34` |
| **I-3** | 마법 상수 기대값 — Profile에서 `M=34` 고정 | Y | 기대값 필드·TC에서 `expected:34` 불일치 노출 |
| **I-4** | 마법 선 레지스트리 — 판정마다 동일 10선 | Y | 동일 격자에 서로 다른 `lineId` 집합 사용 시 회귀 TC 실패; `profileId` 불일치 |
| **I-5** | 판정 오케스트레이터 — 결정성 | Y | 동일 Given 두 번 When → Then 완전 동일 |
| **I-6** | 생성 결과 검증 — 생성물은 1차 검증 통과 | N (2차) | 생성 Slice에서 `Valid` 미달 |
| **I-7** | 입력 경계·명시적 실패 | Y | `InputError`/`Invalid` + 비어 있지 않은 `violations`; `Valid` 오판 없음 |
| **I-8** | 부분 배치 규칙 | N (2차) | `Partial` 및 부분 위반 코드 (1차는 `INCOMPLETE_GRID`만) |

## 4. Test Strategy (TDD)

### 4.1 테스트 피라미드·레벨

```text
        ┌─────────────────────┐
        │ 통합: 오케스트레이터 │  ← TC-001,005,008,012,017 (E2E에 가까운 판정)
        ├─────────────────────┤
        │ 단위: I-1, I-2, I-4 │  ← 선 레지스트리, multiset, 선 합
        └─────────────────────┘
```

| 경계 | 단위 | 통합 |
|------|------|------|
| **마법 선 레지스트리** | 10선 ID·셀 좌표·`M` | Profile 로드 후 규칙에 주입 |
| **I-1 multiset** | 16값만 보고 판단 | 오케스트레이터가 먼저/나중 호출 순서 고정 |
| **I-2 선 합** | 단일 `lineId` | 전체 10선 순회 |
| **입력 어댑터** | 차원·타입 | 잘못된 형식 → `InputError` |

**원칙:** 통합 테스트는 **사용자 관점 계약**(Given 격자 → Then verdict)만 검증; 선 하나의 합 계산은 단위에서 분리.

### 4.2 시나리오 분류

| 분류 | 1차 | 최소 예시 (본 문서) |
|------|-----|---------------------|
| **유효** 완전 배치 | ✅ | TC-001 듀러, TC-002 치환 해, TC-003 경계(1·16 코너) |
| **무효 I-1** | ✅ | TC-004 중복, TC-005 누락, TC-006 범위 밖 |
| **무효 I-2** | ✅ | TC-007, TC-014, TC-015 |

## 6. Red / Green / Refactor Playbook

### 6.1 브랜치별 Definition of Done

| 브랜치 | DoD |
|--------|-----|
| **`spec`** | 본 문서 §1~§8·TC 목록·Decision Log 합의; README “다음 단계” 중 TDD 시나리오 항목 충족 |
| **`red`** | 해당 Slice TC **전부 실패**(또는 미구현으로 실패); **프로덕션 최소 구현 없음**; 스텁은 실패를 유발하는 수준만 허용 |
| **`green`** | 해당 Slice TC **전부 통과**; `@skip`·의도적 pending 없음 |
| **`refactor`** | 전체 TC 녹색 유지; **행위 변경 없음**; 테스트는 리팩터로 깨지면 **명세 오류**로 먼저 문서 수정 |

### 6.2 develop merge 규칙

1. **`green` 또는 `refactor`만** `develop`에 merge (해당 Slice TC 전부 녹색).
2. **`red` 단독** merge 금지 — 실패 테스트만 있는 상태는 `red` 브랜치에 유지.
3. **`spec` 문서**는 코드 없이 `develop`에 merge 가능(본 문서).
4. Slice **역순 merge** 금지 (S3 없이 S4 완료 주장 불가).
5. merge 전 **Profile `MS4X4_STD_V1`** 변경 시 §2.4·TC 동시 갱신.

### 6.3 커밋 메시지 규칙

| 접두사 | 용도 |
|--------|------|
| `docs:` | spec 문서·TC 명세 변경 |
| `test:` | red — 실패 테스트 추가 |
| `feat:` | green — Slice 동작 구현 |
| `refactor:` | refactor — 동작 동일 구조 개선 |

예: `test: S2 add I-1 duplicate scenario (TC-004)`

```text
┌─────────────────────────────────────────────────────────────────┐

│  - 차원·타입·완전성 → InputError (I-7)                           │
└────────────────────────────┬────────────────────────────────────┘
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│ [검증 오케스트레이터 Verification Orchestrator]                  │
│  - Profile MS4X4_STD_V1 로드 (I-4)                              │
│  - 규칙 파이프라인 순서 고정 → 동일 결과 (I-5)                    │
│  - VerdictResult 조립                                            │
└──────┬──────────────┬──────────────┬────────────────────────────┘
       │              │              │
       ▼              ▼              ▼
┌────────────┐ ┌────────────┐ ┌────────────────────┐
│ I-4 선     │ │ I-1 집합   │ │ I-2/I-3 선 합      │
│ 레지스트리 │ │ 규칙       │ │ 규칙 (10선 vs 34)  │
└────────────┘ └────────────┘ └────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│ [생성 Generation]  (2차, I-6) — 1차 경계 밖                      │
│  - 출력은 반드시 오케스트레이터에 통과해야 Valid (I-6)           │
└─────────────────────────────────────────────────────────────────┘
```
