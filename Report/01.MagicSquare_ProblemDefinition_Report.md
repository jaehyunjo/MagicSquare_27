## STEP 1 — Observation (관찰)

### 1. 현재 우리가 해결하려는 상황은 무엇인가?

**관찰:**  
누군가는 **4×4 격자에 1부터 16까지의 정수를 한 번씩 배치**했을 때, **여러 “줄”(행·열·대각선 등)의 합이 동일한지**를 다루는 상황에 있다.

즉, “무언가를 만든다”기보다,

- **규칙이 있는 배치**가 존재하는지,
- **그 규칙을 만족하는 배치를 어떻게 얻는지**(찾기·생성·검증),
- **그 결과를 사람이나 다른 시스템이 어떻게 확인·활용하는지**

를 다루려는 **불확실성·제약·검증**이 있는 상황이다.

**상황을 한 문장으로:**  
“16개의 서로 다른 숫자를 4×4에 놓았을 때, 정해진 여러 선(행·열·대각 등)의 합이 모두 같아야 한다”는 **조합·산술 제약**을 프로그램으로 다루려는 출발점이다.

### 2. 왜 4×4 마방진 문제를 다루는가?

| 관점 | 관찰 |
|------|------|
| **규모** | 3×3보다 제약·패턴이 풍부하고, 5×5 이상보다는 **수·경우·규칙을 손으로/도구로 추적하기 쉬운** 크기 |
| **학습** | “모든 줄의 합이 같다”는 **불변량(마법 상수)** 개념, **대칭·회전·치환**, **탐색·휴리스틱·템플릿**을 짧은 주기로 경험하기 좋음 |
| **구현** | 입력·출력·검증 루프가 단순해 **문제 정의 → 요구사항 → 테스트** 흐름을 연습하기에 적당 |
| **현실과의 거리** | 스케줄링, 배치, 제약 만족(CSP) 등 **“격자 + 합/한도 제약”**의 축소판으로 읽히기 쉬움 |

**“왜 마방진인가?”에 대한 관찰적 답:**  
단순 퍼즐이 아니라, **제약을 만족하는 배치를 찾거나 증명하는 연습**—즉 **규칙 기반 상태 공간**을 다루는 대표 사례로 4×4가 자주 선택된다.

### 3. 어떤 학습 또는 시스템 설계 맥락에서 등장하는가?

**학습 맥락**

- **알고리즘·자료구조:** 2차원 배열, 순열/조합, 탐색, 가지치기
- **수학·논리:** 합 불변, 대칭, 동형(같아 보이는 배치), 해의 개수
- **소프트웨어 공학:** 요구사항(어떤 선까지 “마법”인지), 경계 조건, 검증 vs 생성 역할 분리
- **테스트·명세:** “올바른 배치”의 **정의를 명세와 맞추는** 연습

**시스템 설계 맥락**

- **도메인 모델:** 격자, 셀, 선(행/열/대각), 마법 상수
- **기능 분리:** 생성 / 검증 / 표시·입력 / (선택) 해 탐색·통계
- **확장 가능성:** 차원·변형·N×N 일반화
- **품질:** 잘못된 입력, 중복 숫자, 부분만 채운 격자, “거의 맞는” 배치 처리

### 관찰 관점 요약 (표현 전환)

| 피하고 싶은 표현 | 관찰 관점 표현 |
|------------------|----------------|
| “마방진을 만든다” | “16개 정수의 4×4 배치에서, 정의된 여러 선의 합이 동일한지 탐색·검증·제시한다” |
| “프로그램을 짠다” | “제약 만족 문제의 한 인스턴스를, 명세 가능한 형태로 다룬다” |
| “퍼즐을 푼다” | “규칙·불변량·해 공간을 학습·설계·구현 관점에서 분리해 본다” |

### 열려 있는 질문 (관찰 단계)

- 목표가 **해 하나 생성**, **모든 해 열거**, **사용자 입력 검증**, **교육용 UI** 중 어디에 가까운지
- “마법”에 **어떤 선**까지 포함하는지
- **짝수 4×4**는 홀수 차수와 절차가 달라 **문제 정의가 갈라지는 지점**이 됨

## STEP 2 — Why #1

### Q: 왜 마방진을 완성해야 하는가?

#### 가정 A (답)

> **“모든 행·열·대각선의 합이 동일한 4×4 배치를 하나 확보해야, 그 배치가 ‘올바른 마방진’인지 검증·시연·제출할 수 있기 때문이다.”**

즉, **완성된 격자 = 규칙을 만족한다는 증거**이고, 미완성·부분 배치는 “맞는지 틀린지”를 말하기 어렵다는 전제 위에 “완성”이 필요하다.

### A에서 드러나는 불편함 · 구조적 문제

#### 1. “완성”과 “목적”이 뒤섞임

| 표면 이유 | 구조적 문제 |
|-----------|-------------|
| 완성해야 검증·제출 가능 | **검증**만 필요하면 “완성된 해 하나”가 아니라 **검증 + 임의 입력**으로도 목적 달성 가능 |
| 완성 = 증거 | **생성**과 **검증**이 한 목표(완성)에 묶여 요구사항이 커짐 |

**불편함:** “왜 완성하나?”에 대한 답이 곧바로 **“시스템이 생성기여야 한다”**로 슬라이딩됨. **학습자가 손으로 채우고 시스템은 판정만** 하는 시나리오와 충돌.

#### 2. “하나” vs “해의 다양성”

4×4 마방진은 **동일 합을 만족하는 배치가 여러 개**(대칭·치환으로 동형 해가 많음).

- “완성한다” = **임의의 유효 해 하나**인지, **특정 표준 형태**인지, **모든 해**인지 불명확.
- A는 **대표 샘플 하나**에 만족하지만, 사용자는 **“내가 만든 배치가 맞나?”**를 물을 수 있음.

**불편함:** 완성을 목표로 두면 **“틀렸지만 거의 맞는” 배치**에 대한 요구(힌트, 어디가 어긋나는지)가 설계 밖으로 밀려남.

#### 3. 완성 시점이 모호함

- 16칸 전부 채워야만 “완성”인가?
- 부분 채움은 “부분 완성”인가?
- **자동으로 채워 주는 것**까지 “완성”에 포함되는가?

A는 **최종 상태 스냅샷**만 말하고, **과정(단계별 채우기)** 은 다루지 않음.

#### 4. “완성해야 한다”는 압박이 만드는 잘못된 최적화

| A의 암묵적 가치 | 부작용 |
|-----------------|--------|
| 빨리 유효한 4×4를 얻는 것 | 무작위·완전 탐색으로 가기 쉬움 |
| 완성 = 성공 | **왜 그 배치가 성립하는지** 설명·추적은 비목표가 됨 |
| 하나만 있으면 됨 | **재현 가능한 절차** 학습 목표와 어긋날 수 있음 |

#### 5. 짝수 차수(4×4) 특유의 균열

“완성해야 한다”는 이유만으로는 **4×4 전용 절차를 배울지, 일반 제약 만족으로 갈지** 분기가 안 보임.

#### 6. 이해관계자·맥락이 빠져 있음

- **누가** 완성해야 하는가?
- **언제** 완성이 끝인가?
- **실패**하면 무엇이 문제인가?

### 요약: A가 드러내게 한 “진짜 긴장”

```text
완성(산출물)  ←——→  이해(과정·규칙)
     ↑                    ↑
  A가 강조              A가 말하지 않음
```

- **A로 읽히는 핵심:** “유효한 최종 격자가 있어야 ‘마방진’ 주장을 입증할 수 있다.”
- **구조적 문제:** 목표가 **생성·완성**에 치우치면 **검증·탐색·교육·부분 상태**가 같은 “완성” 말 아래 숨어 요구사항이 갈라짐.

## STEP 3 — Why #2

### Q: 왜 단순 계산이 아니라 프로그램으로 구현하는가?

**“단순 계산”:** 손계산·종이 격자·계산기로 행·열·대각 합을 맞춰 보는 방식.  
**“프로그램”:** 규칙·데이터·절차를 실행 가능한 형태로 둔 방식.

### 1. 반복 가능성 (Repeatability)

| 단순 계산 | 프로그램 |
|-----------|----------|
| 시도마다 집중력·순서·실수가 달라짐 | **동일 입력 → 동일 절차 → 동일 결과**(의도한 범위 내) |
| 다른 해·다른 시작 조건 비교가 번거로움 | **매개변수·반복 실행**으로 같은 기준으로 비교 |
| “어제 맞췄던 방법”이 말로만 남음 | **절차가 명문화**되어 재현·공유 가능 |

**답:** 마방진은 **한 번의 합 맞추기**가 아니라, **같은 규칙을 여러 배치·여러 전략에 반복 적용**하는 문제에 가깝다.

**긴장:** 반복 가능성을 위해 구현하면 목표가 **“한 번 완성”**에서 **“실험·탐색 플랫폼”**으로 넓어질 수 있음.

### 2. 검증 자동화 (Automated verification)

| 단순 계산 | 프로그램 |
|-----------|----------|
| 행·열·대각을 사람이 각각 더함 | **검증 루프**가 정의와 대응 |
| “대각도 봤나?” 누락 가능 | 체크리스트 고정 |
| 부분 격자는 “아직 모름”과 “틀림”이 애매 | **부분 검증**도 동일 규칙으로 처리 가능 |

**답:** **“완성된 배치 = 증거”**는 사람이 다시 더해 확인하는 것보다 **검증기가 같은 기준으로 즉시 판정**할 때 안정적이다.

**긴장:** 검증만 필요하면 **생성기 없이도** 가치가 있음 → **검증 vs 생성** 역할 분리 필요.

### 3. 오류 방지 (Error prevention)

오류 유형:

1. **산술 오류** — 합 계산 실수  
2. **규칙 오류** — 중복·누락, 잘못된 선만 검사  
3. **절차 오류** — 채우는 순서·가정이 틀림  

**답:** 4×4는 손으로도 가능해 보이지만, 이점은 **크기**보다 **제약 개수와 검사 횟수**에 비례한다.

**긴장:** 오류 방지를 과도하게 맞추면 **사용자가 스스로 실수하며 배우는 과정**이 줄어듦.

### 4. 규칙 기반 사고 훈련

- **규칙:** 어떤 선의 합이 같아야 하는가  
- **불변량:** 마법 상수, 숫자 집합  
- **상태:** 격자의 각 칸  
- **추론:** 한 칸을 정하면 다른 칸의 가능성이 줄어듦  

**답:** 구현은 **답 하나를 구하는 계산**이 아니라 **“제약을 만족하는 상태를 규칙으로 다루는 연습”**이다.

**긴장:** “규칙 기반 사고”를 목표로 하면 **무차별 시도만**으로는 훈련 목표에 부족할 수 있음.

### 네 관점 통합 (한 문단)

**단순 계산**은 4×4 한 장을 **한 번의 인지·산술 이벤트**로 다루기 쉽고, **프로그램**은 같은 문제를 **반복 가능한 실험**, **명세에 맞는 자동 판정**, **기계적 실수 제거**, **규칙을 외부화한 사고 훈련**의 대상으로 바꾼다.  
즉, “34가 나오게 더한다”가 아니라 **“정의된 제약系을 안정적으로 다루는 시스템”**이 필요할 때 구현이 정당화된다.

### STEP 2와 STEP 3 연결

| 관점 | Why #1(A)와 맞을 때 | 충돌·주의 |
|------|---------------------|----------|
| 반복 가능성 | 여러 해·전략 비교 | “하나만 완성”으로 범위 축소 |
| 검증 자동화 | 완성품 증명 | 생성 없이도 충분 |
| 오류 방지 | 자동 채우기·검사 | 학습용 실수 허용 vs 차단 |
| 규칙 기반 사고 | 절차·CSP 학습 | 범위·난이도 결정 필요 |

## STEP 4 — Why #3 (핵심 발견)

### Q: 왜 이 문제를 TDD 방식으로 설계하려 하는가?

TDD는 **“먼저 돌아가는 것”이 아니라 “먼저 고정되는 의미(명세)”**를 두는 설계 방식이다. 4×4 마방진은 **수학적 불변량이 분명**하고 **입출력이 격자로 고정**되어 TDD와 잘 맞는다.

### 1. 무엇이 통제되어야 하는가?

| 통제 대상 | 왜 통제해야 하는가 |
|-----------|-------------------|
| **“마방진”의 정의** | 생성 vs 검증 혼선 방지 |
| **입력의 유효성** | 빈 칸, 중복, 범위 밖, 크기 |
| **부분 vs 완전 상태** | “완성” 시점 모호함 해소 |
| **역할 경계** | 생성 / 검증 / 표시 |
| **결정성·반복** | 같은 입력 → 같은 판정 |
| **마법 상수·집합** | 정의 오류 조기 차단 |

**핵심 발견:** 통제 대상은 **UI 세부가 아니라 “어떤 격자를 올바르다고 부를 것인가”**와 **각 컴포넌트의 계약**이다.

### 2. 어떤 불변 조건이 존재하는가?

#### (A) 도메인 불변량

| 불변 조건 | 4×4, 1~16일 때 |
|-----------|----------------|
| **숫자 집합** | 1~16 각 정확히 한 번 |
| **마법 상수** | 모든 “마법 선”의 합 = 34 |
| **선 집합** | 어떤 선을 “마법”에 포함할지 고정 |
| **대칭·동형** (선택) | 회전·반사 후 판정 — 범위 선택 사항 |

#### (B) 시스템 불변량

| 불변 조건 | 내용 |
|-----------|------|
| **검증의 순수성** | 같은 격자 → 같은 판정 |
| **검증 ⊇ 생성** | 생성 결과는 반드시 검증 통과 |
| **부분 검증의 단조성** | 정의할 경우 일관된 부분 규칙 |
| **오류 입력 처리** | 조용한 “거의 맞음” 금지 등 |

#### (C) TDD에서의 쓰임

- **Red:** 유효·무효 격자 케이스  
- **Green:** 최소 구현  
- **Refactor:** 구현 변경 시에도 (A)(B) 유지  

**핵심 발견:** TDD는 **수학적 정의를 명세와 동기화**하는 장치. 4×4는 손으로도 가능해 **구현이 정의를 대체**하는 위험이 있음.

### 3. 왜 입력/출력이 명확해야 하는가?

**입력:** 격자 표현, 빈 칸 의미, 4×4 고정 여부, “현재 격자 스냅샷” 통일.  
**출력:** 판정(bool / 오류 목록), 생성 결과, 실패 표현.

**핵심 발견:** 입출력이 명확해야 **“완성 = 증거”**가 **`판정 → 참/거짓(및 설명)`**으로 번역된다. 흐리면 생성·검증이 한 덩어리가 되고 부분·거의 맞음을 다루기 어렵다.

### TDD Why 종합

**한 문장:**  
4×4 마방진은 **불변량이 수학적으로 정해져 있고**, 가치는 **그 불변량을 자동·반복·무오류로 판정**하는 데 있으므로, **먼저 테스트로 의미를 고정(TDD)** 하면 **생성·검증·완성의 혼선**을 막고 **회귀 없이** 절차를 바꿀 수 있다.

```text
        [명확한 입력: 격자 스냅샷]
                    │
                    ▼
            ┌───────────────┐
            │  검증 (먼저)   │
            └───────┬───────┘
                    │ 통과해야 함
                    ▼
            ┌───────────────┐
            │  생성 (나중)   │
            └───────┬───────┘
                    ▼
        [명확한 출력: 판정 / 설명 / 격자]
```

## STEP 5 — 진짜 문제 정의

### 1. 표면 문제 정의 (잘못된 정의)

> **4×4 격자에 1부터 16까지 숫자를 넣어, 행·열·대각선의 합이 모두 같게 만드는 프로그램을 만든다.**

#### 왜 잘못된 정의인가

| 한계 | 설명 |
|------|------|
| **목표가 산출물에만 묶임** | 판정·반복·학습이 빠짐 |
| **“마방진”의 범위가 없음** | 선·숫자 집합·중복 규칙 미명시 |
| **주체가 불명확** | 누가 채우는지, 완료 시점 불명 |
| **성공 기준이 단일함** | 한 번 맞추기 vs 비교·설명 |
| **역할이 섞임** | 만들기·검사·표시가 한 덩어리 |

### 2. 개선된 문제 정의 (정확한 정의)

> **4×4 격자에 대한 “마방진” 판정 기준을 먼저 고정하고,  
> 임의의 배치(완전·부분·잘못된 입력 포함)에 대해 그 기준을 일관되게 적용·반복·기록할 수 있는지를 다루는 문제이다.  
> 필요 시, 그 기준을 만족하는 완전한 배치를 얻는 행위는 **판정 기준을 만족하는 산출물을 확보하는 것**으로만 정의하며,  
> 손으로 한 번 맞추는 것과 동일한 수준의 “계산”이 아니라, **규칙·불변량·경계를 명세 가능한 형태로 다루는 능력**을 검증한다.**

#### 정의에 포함되는 것

| 요소 | 내용 |
|------|------|
| **대상** | 4×4 격자 위 16칸 배치 상태 |
| **선행 조건** | “마방진” 정의(숫자 집합, 마법 선) 사전 고정 |
| **핵심 행위** | 기준에 따른 **판정**; 동일 기준의 **반복 적용** |
| **부가 행위** | (범위 한정 시) 기준을 만족하는 **완전** 배치 확보 |
| **성공** | 판정이 기대와 일치하고 **재현** 가능 |
| **실패** | 기준 위반·입력 위반·역할 혼선이 **구분**됨 |

#### 의도적 비목표에 가까운 것

- 특정 배치를 “예쁘게” 보여 주는 것만이 목적이 아님  
- 일회성 산술 연습만이 목적이 아님  
- 규칙 없는 시행착오만 반복하는 것은 목적이 아님  

### 3. 이 문제의 핵심 Invariant

#### 도메인 불변량

| ID | 불변 조건 | 위반 시 |
|----|-----------|---------|
| **I-1** | 정해진 16개 정수 각 **정확히 한 번** | 후보 해 아님 |
| **I-2** | 정의된 모든 “마법 선”의 합이 **서로 같음** | 마방진 아님 |
| **I-3** | 공통 합(마법 상수)은 크기·집합에 **논리적으로 결정** | 정의·적용 모순 |
| **I-4** | 판정에 쓰는 규칙 집합은 **판정마다 동일** | 같은 격자에 말이 바뀜 |

#### 시스템·과정 불변량

| ID | 불변 조건 | 위반 시 |
|----|-----------|---------|
| **I-5** | 동일 완전 배치·동일 기준 → **동일 판정** | 반복·신뢰 붕괴 |
| **I-6** | 완전 배치 확보 결과는 **항상 I-1~I-3 만족** | 생성·판정 어긋남 |
| **I-7** | 잘못된 입력은 **조용히 “거의 맞음” 처리 안 됨** | 오류 방지 실패 |
| **I-8** | 부분 배치 시 부분 판정 규칙 **사전 정의·일관** | 완성 시점 모호 |

#### 우선순위 (개념적)

```text
I-4 (판정 기준 고정)
    → I-1, I-2, I-3 (도메인)
        → I-5, I-7 (판정 행위)
            → I-6 (완전 배치 확보 — 선택)
                → I-8 (부분 상태 — 선택)
```

### 4. 우리가 실제로 훈련하려는 사고 능력

| 능력 | 훈련 내용 |
|------|-----------|
| **명세화** | “맞다”를 **검사 가능한 조건**으로 표현 |
| **불변량 사고** | 지켜야 할 것 vs 바뀌어도 되는 것 구분 |
| **경계·계약 사고** | 허용·거부·부분 처리 구분 |
| **역할 분리** | 판정·생성·표현을 섞지 않음 |
| **반복·회귀 의식** | 다시 실행해도 의미 유지 |
| **반증·오류 설계** | 위반 유형을 의도적으로 구분 |
| **증거와 주장** | “맞다” = **기준 통과** |
| **규칙 기반 추론** | 한 칸·한 선이 나머지 가능성에 미치는 영향 |

#### 한 줄 훈련 목표

> **제약이 있는 유한 상태(4×4 배치)에 대해,  
> 고정된 규칙으로 참·거짓을 말하고,  
> 그 말이 바뀌지 않도록 경계와 불변량을 스스로 명확히 하는 사고.**

### STEP 5 요약 대조

| 구분 | 표면 (잘못된) | 개선 (정확한) |
|------|----------------|----------------|
| **한 줄** | 마방진을 만든다 | 마방진 **기준**을 고정하고 배치를 **일관되게 판정·반복** |
| **성공** | 격자 하나 완성 | 판정·불변량·경계가 명확하고 재현 가능 |
| **핵심** | 합 맞추기 | 불변량(I-1~I-8)과 사고 능력 |
| **위험** | 생성·검증·표현 혼선 | 계약·역할이 문서화되지 않음 |
